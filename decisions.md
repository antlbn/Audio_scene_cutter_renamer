
# Decisions

## UI/UX settings: первый этап

Текущий фокус: не делать весь большой settings-wizard сразу. В MVP settings
закрывает только один основной use case пайплайна и редактирует секцию
`whisper` в `config.yaml`.

- `cinema_clapboard -settings` открывает терминальный UI на InquirerPy: сначала
  главное меню настроек, внутри можно менять отдельные пункты, в конце
  `Done / Save`.
- В первом этапе доступны только:
  - язык аудиодорожки для Whisper (`whisper.language`);
  - режим Whisper: `transcribe` или `translate` (`whisper.task`);
  - локальная модель Whisper (`whisper.model_id`).
  - просмотр и удаление локально скачанных весов Whisper из `whisper.cache_dir`
    через отдельный пункт меню с подтверждением.
- Следующий UI-этап:
  - настройка `clapper.audio_model.threshold`;
  - настройка рендеринга нового имени файла через `renamer.naming_template`;
  - настройка суффикса через `renamer.suffix`.
- В JSON итогового результата поле `new_name` хранит финальное имя файла.
- Рендеринг имени файла теперь настраивается через отдельный `renamer`-блок,
  а заданный суффикс просто дописывается к шаблону без проверок.
- Язык выбирается через settings и хранится в конфиге.
- Settings UI редактирует тот же `config.yaml`, потому что один хорошо
  прокомментированный конфиг проще для пользователя. Для записи используется. Дефолтный конфиг храниться отдельно, и если надо загружается по команде из меню settings
  round-trip YAML parser (`ruamel.yaml`), а не ручная правка строк, чтобы не
  плодить костыли и сохранять комментарии.
- Python CLI (`pipeline.py`, `whisper.py`) пока оставляет `--language` и `--task`
  как dev/debug override, но пользовательский путь через wrapper идет от
  `config.yaml`.
- Остальные идеи settings, такие как rename mode, JSON рядом с файлом, output
  folder, OpenAI/cloud Whisper, .env wizard, prompt/model docs и удаление весов,
  остаются roadmap и не входят в первый этап.

# Batch mode: почему не bash-loop

При обработке нескольких файлов через bash-loop (`for f in *.wav; do cinema_clapboard $f; done`)
каждый вызов — это новый Python-процесс.  
CLAP-модель (~600 MB) и Whisper загружаются заново на каждом файле.  
При 20 файлах это 20 загрузок вместо 1 — медленно и дорого по памяти.

Решение: `batch_runner.py` держит один Python-процесс на всю сессию.  
В нём живёт `_RUNTIME_CACHE` из `clapper.py` — модели загружаются ровно один раз.

---

# Batch mode: сценарий ошибки при обработке файла

При пакетной обработке ошибка на одном файле не должна останавливать всё.  
Сценарий:

```
[1/5] ✅ ZOOM0001_Tr1.wav → Sequence_01_shot_01_dubl_2_Tr1.wav
[2/5] ✅ ZOOM0001_Tr2.wav → Sequence_01_shot_01_dubl_2_Tr2.wav
[3/5] ❌ ZOOM0002_Tr1.wav — ошибка: AudioLoadError: unsupported codec
       ↳ файл пропущен, продолжаем
[4/5] ✅ ZOOM0003_Tr1.wav → Sequence_01_shot_02_dubl_1_Tr1.wav
[5/5] ✅ ZOOM0003_Tr2.wav → Sequence_01_shot_02_dubl_1_Tr2.wav

Итог: 4 успешно / 1 ошибка
```

Ошибка логируется через `LOGGER.exception()` и выводится в терминал,  
но не поднимает исключение наверх — цикл продолжает следующий файл.  
В конце — сводка: сколько успешно / сколько упало.

# Поддерживаемые аудио-форматы (batch mode)

Список форматов для рекурсивного поиска в директории:

```
.wav, .mp3, .flac, .aac, .m4a, .ogg, .aif, .aiff, .bwf, .rf64
```

Источник: типичные форматы полевых рекордеров (ZOOM, Sound Devices, Tascam).  
CLAP грузит через torchaudio + ffmpeg-fallback, технически поддерживает всё что умеет ffmpeg.

# Архитектура batch mode: единый оркестратор

## Решение

Вместо двух отдельных скриптов (pipeline.py для одного файла, batch_runner.py для директории)
— один оркестратор `batch_runner.py`, который обрабатывает оба use case.

`cinema_clapboard` (bash) всегда вызывает один и тот же Python-скрипт.  
Внутри него — ветвление по типу аргумента.

## Use cases

| Сценарий | Поведение |
|---|---|
| `cinema_clapboard audio.wav -rename` | один файл → сразу пайплайн, без TUI |
| `cinema_clapboard ./recordings/ -rename` | директория → TUI checkbox → пайплайн × N |

## Схема вызовов

```
cinema_clapboard (bash)
    └── batch_runner.py  ← единственный CLI-оркестратор
            │
            ├── [аргумент — файл]
            │       └── pipeline.run_pipeline(file)
            │               └── presentator_cli.present()
            │
            └── [аргумент — директория]
                    ├── scan: найти все аудио-файлы рекурсивно
                    ├── показать: настройки (--rename, --json, шаблон)
                    ├── TUI: InquirerPy checkbox → пользователь снимает лишнее
                    ├── спросить: y/N
                    └── для каждого выбранного файла:
                            ├── pipeline.run_pipeline(file)
                            ├── presentator_cli.present()
                            └── ошибка? → лог + продолжить следующий
                                         (не останавливаться)
```

## Роли файлов (финальные)

| Файл | Роль |
|---|---|
| `cinema_clapboard` | bash-обёртка, точка входа для пользователя |
| `batch_runner.py` | **единственный CLI-оркестратор** (новый файл) |
| `pipeline.py` | библиотека: `run_pipeline()` — обработка одного файла |
| `pipeline.main()` | остаётся как dev/debug точка входа для разработчика |

## Почему не bash-loop

`_RUNTIME_CACHE` в `clapper.py` кэширует CLAP-модель (~600 MB) внутри одного Python-процесса.  
bash-loop запускает N новых процессов → N загрузок модели.  
Один оркестратор держит процесс живым → модель грузится **ровно один раз** на всю сессию.
